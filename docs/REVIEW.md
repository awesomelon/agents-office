# Codex 전용 전환 및 프로젝트 평가

기준 버전: 기존 `a6c1bca` → Codex Office `0.2.0` 변경안.

## 평가

**기존 4.1/10 → 개선안 8.6/10.** 점수는 아래 가중치를 적용한 기술적
판단이며 외부 인증이나 사용자 만족도 측정치가 아니다. “12점짜리”는
기대 이상의 완성도를 목표로 해석했다. 미검증 영역이 있으므로 만점이나
척도를 벗어나는 점수로 포장하지 않는다.

| 평가 영역 | 비중 | 기존 | 개선안 | 근거 |
| --- | ---: | ---: | ---: | --- |
| 핵심 기능·동작 정확성 | 30% | 4.0 | 8.5 | 빌드 실패 수정, Codex 형식·경로·호출/결과·스레드 처리 |
| 안정성·개인정보 처리 | 25% | 3.0 | 8.5 | 원문 미노출, 읽기/메모리 상한, 부분 기록·파일 교체·초기 상태 경합 처리 |
| 사용성·접근성 | 20% | 6.0 | 8.5 | 명시적 데모, 연결 안내, 검색·필터·상세, 키보드 조작·반응형·모션 설정 |
| 유지보수·검증 | 15% | 4.0 | 9.0 | 회귀 테스트, 실제 Rust 코어 재사용 테스트, CI, 문서·버전 일치 |
| 배포 신뢰성 | 10% | 3.0 | 8.5 | 비동기 잠금, 체크섬, 토큰 전달 제한, 검증된 캐시 교체, 구 릴리스 차단 |

가중 평균: 기존 4.05, 개선안 8.575. 기존 평가는 원래 제품으로서의 상태를
포함하며 Codex 적합도만 평가한 점수는 아니다. 기존 버전은 Codex를 지원하지 않는다.

## 발견한 핵심 문제와 수정

1. **기존 프로덕션 빌드 실패.** `vite.config.ts`가 설치되지 않은
   `@tauri-apps/plugin-fs`와 `plugin-shell`을 수동 청크에 넣고 있었다.
   실제 사용하는 API만 남겨 빌드를 복구했다.
2. **Claude 전용 수집과 부정확한 로그 해석.** 경로를 Codex 세션으로
   변경하고, 중첩 rollout envelope를 명시적으로 파싱한다. 알 수 없는
   레코드를 빈 메시지로 표시하지 않는다. 세션/호출별 결과를 연결한다.
3. **감시 상태와 초기 이벤트 경합.** 실제 소스 상태를 표시하고,
   구독 후 원자적 스냅샷을 읽어 revision 이후의 이벤트만 적용한다.
4. **기존 작업 재생·부분 바이트 손실·메모리 증가.** 기존 파일은 EOF에서
   시작하며 헤더로만 스레드를 식별한다. UTF-8 바이트 조각, 파일 축소와
   교체를 처리하고 소스 탐색·읽기·보관량에 상한을 둔다.
5. **화면과 측정값의 오해.** 책상은 실제 에이전트 수가 아니라 활동 역할로
   명시한다. HUD 응답 시간은 세션과 호출 ID 및 로그 시각으로 계산하며,
   연결할 수 없는 결과에 가짜 시간을 부여하지 않는다.
6. **캔버스 종료 시 충돌과 CSP 충돌.** 문서 이동 종료 시 조건부 훅 호출을
   제거했다. 0 크기 계산과 WebGL 실패를 처리하고, 공식 Pixi 정적 셰이더
   모듈로 CSP를 약화하지 않고 호환한다. 숨겨진 화면의 애니메이션을 줄였다.
7. **실행기의 비동기 잠금·배포 무결성.** 잠금은 다운로드 완료까지 유지한다.
   HTTPS 리디렉션에 GitHub 토큰을 무조건 전달하지 않고, 해시를 검증한 뒤
   캐시를 교체한다. Codex 전용 파일명이 없는 이전 릴리스는 실행하지 않는다.
8. **작업 지침·버전·검증 부재.** 오래된 Claude 지침 49개를 간결한
   `AGENTS.md`로 통합했다. 버전을 0.2.0으로 맞추고 앱용 잠금 파일,
   회귀 테스트와 CI를 추가했다. 발견된 전이 의존성 `qs` 취약점도
   허용된 버전 범위 내 업데이트로 해결했다.
9. **네이티브 번들 검증에서 추가 발견한 Tauri 버전 불일치.** macOS CI의
   전체 Rust 컴파일·테스트는 통과했으나 앱 번들 단계가 Rust 2.11과
   JavaScript API 2.9의 불일치로 실패했다. 두 계열을 2.11로 맞추고
   잠금 파일의 major/minor 일치를 메타데이터 검사에 추가했다.

## 검증 범위

최종 로컬 검증에서 **84개 테스트**가 통과했다: 프론트엔드 39개,
실행기 22개, Rust 코어 23개. Rust 포맷 검사와 Clippy 경고 0건도 확인했다.

- `npm run check`: 버전 메타데이터, TypeScript, 프론트엔드·실행기 테스트,
  프로덕션 웹 빌드.
- 실제 UI 컴포넌트를 jsdom에서 조작해 데모 재생/정지/초기화,
  연결 오류와 재연결, 검색·유형·세션 필터·상세·표시 지우기를 검증했다.
- React 컴포넌트의 이동 애니메이션 종료와 모션 설정 전환을 재현했다.
  동적 함수 생성을 차단한 상태에서 실제 Pixi 셰이더 초기화와 uniform
  전달 로직을 실행했다. 완전한 WebGL 렌더링 테스트와는 구분한다.
- Rust 코어는 데스크톱이 사용하는 소스를 직접 불러와 합성 JSONL과
  임시 파일로 파서·tailer·감시 상태를 검증한다.
- `npm audit --omit=dev`: 검사 시점의 운영 의존성 알려진 취약점 0건.
  이 결과가 애플리케이션 전체의 무결함을 증명하는 것은 아니다.
- `npm pack --dry-run`으로 배포 패키지 구성을 확인했다.

## 남은 한계와 출시 조건

로컬 브라우저 접근은 실행 환경의 `ERR_BLOCKED_BY_CLIENT`로 차단되었다.
따라서 화면 스크린샷, 실제 작은 화면 레이아웃과 WebGL 결과를 육안 검증한
것으로 주장하지 않는다. jsdom 검증은 이를 대체하지 않는다.

전체 Linux Tauri 확인은 `pkg-config`와 GTK/WebKit 시스템 의존성이 없어
진행되지 못했다. 별도의 macOS CI는 전체 앱 빌드 경로를 확인하도록
구성했으며, 실제 Codex 세션과 macOS 앱 실행·Gatekeeper·서명/공증 검증은
출시 전에 필요하다. 이 작업은 npm이나 GitHub Release를 발행하지 않는다.

Codex rollout은 내부 형식이다. 승인 대기·프로세스 생존 상태를 완전하게
관측할 수 없고 JSONL을 남기지 않는 Codex 호스트는 지원되지 않는다.
기능 범위와 개인정보 보호 경계는 README에 명시했다. 지원할 Codex 버전을
고정하고 실제 사용자 세션·배포 기기에서 검증하는 것이 다음 점수 향상의
근거가 된다.
